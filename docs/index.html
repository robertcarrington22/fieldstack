How it works

Four systems.
One sheet.

  1. Read ProcoreRFIs, submittals, daily logs, change orders. Read-only token on one project.
  2. Pull the ledgerJob cost by cost code from Sage 300 CRE or Vista. Accounting owns the dollars.
  3. Pull the scheduleMilestones from P6 or MS Project. The scheduler owns the dates.
  4. Compute, then writeAging, dollars, and percents are computed in code. Claude drafts the prose and cites every record. Your PX approves.

Why you can send it

The model never
does the math.

Owners and lenders forward this report with draw requests. It has to be right. So the parts that can be wrong are computed in code, and the model only writes around them.

Verified
RULE 01

Computed, not guessed

RFI aging in business days against your contract window. Overdue submittals. Pending change-order dollars. Dollar-weighted percent complete. Projected cost. All plain Python, all testable.

Cited
RULE 02

Every claim has a record

The narrative is drafted from the computed facts only and must cite a ref for every sentence with a number in it. Citations render as links back to Procore.

Approved
RULE 03

A person hits send

Nothing is posted back to any system and nothing goes to the owner on its own. Your PX reads it, edits what they want, and sends it. Usually in under half an hour.
